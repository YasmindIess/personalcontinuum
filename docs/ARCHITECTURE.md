# Architecture — Substrate / Lattice / Multiplex

Personal Continuum is organized as five coupled strata rather than one page.

## S0 — Persistent substrate

Canonical, versioned public signals, relation seeds, receipts, and source references. This layer must be render-independent. A browser may destroy every SVG node without destroying the continuum's addressable state.

## S1 — Evidential lattice

Relations among public origins are typed edges, not generic social links. An edge may carry semantic overlap, operator adjacency, structural correspondence, provenance continuity, response history, or independent verification. Missing evidence is represented as missing evidence rather than a synthetic score.

## S2 — Situated render membrane

The renderer materializes only the active origin and bounded neighbors. V2.1 empirically established this direction by holding active heavy artwork to a 3–5 SVG window. Production should virtualize the entire tile shell as well, not only the artwork.

## S3 — Relation multiplex

A single pair of origins can hold multiple Relation Seeds over time. Their projections may disagree. The multiplex preserves each typed relation and its lineage instead of flattening the pair to one edge weight.

## S4 — Public projection / response ingress

Thread posts, deep links, replies, corrections, claims and later external attestations are projections or ingress events. Publishing is not an authority escalation. A social response becomes new evidence only after ingestion and receipt creation.

## Dependency law

`public projection -> relation seed -> evidence/provenance -> canonical public signals`

Rendering may depend on the model. The model must never depend on a renderer or social platform.
