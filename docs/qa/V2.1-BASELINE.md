# V2.1 QA Baseline — 2026-09-28

The V2.1 Chromium harness established a reproducible local baseline before repository modularization.

## Proven by the run

- Dedicated Node QA server verified before capture.
- 202 screenshots captured: two viewports × intro + 50 stable + 50 removal states.
- Four 25/25 contact sheets generated.
- Local page settle time: 517 ms in the Puppeteer runtime report.
- Virtualized artwork window: 3 SVG roots at edges, 5 through interior checkpoints.
- Desktop Lighthouse: FCP/LCP ≈ 0.4 s; Speed Index ≈ 1.0 s.
- Mobile Lighthouse: FCP ≈ 1.9 s; LCP ≈ 2.0 s; Speed Index ≈ 3.4 s.

## Remaining pressure

- DOM remains ~3,106 elements because all 50 textual shells stay mounted.
- Mobile main-thread work remains ~2.5 s; style/layout dominates.
- Mobile typography contains too much sub-12px text.
- Missing favicon causes the console-error best-practice failure.
- Missing meta description in V2.1 causes an SEO failure; the modular app adds one.
- Local server does not test production compression/security headers; those belong to deployment QA.

## Design finding from contact sheets

Desktop composition is coherent but overly rhythmic: the ten base operator families repeat visibly every ten ranks. Mobile crops the seven-word projection too aggressively and suppresses the evidence/value layer. V3 must introduce a 50-instance operator grammar rather than ten repeated illustrations and a responsive disclosure model rather than desktop composition scaled downward.
